## Migration file names
The hosted project records its own timestamp for each migration applied through the Supabase connector. To keep local files and hosted history identical (so a later `supabase db push` won't try to re-apply them), the local files now use the hosted versions:
- `20261022000100_initial_schema.sql` → `20261022034820_initial_schema.sql`

## Free-plan trade-offs (accepted under D33)
- Supabase Free pauses after 1 week without activity and has no automatic backups. Limits: 500 MB database, 1 GB file storage. 🟠 About 1 GB of PDFs is roughly 100–300 papers in total, so the beta must stay small.
- Mitigation: manual export before risky changes; durable job records so work survives restarts.

## 🟢 D34 — free host for the API and worker (decided: option A)
🔵 Facts checked 2026-10-22 (re-check on signup):
- **Render Free:** web services only. Spins down after 15 minutes without inbound traffic; wake-up takes about a minute; 750 free hours a month. No free background worker type.
- **Koyeb Free:** one free web service per account, Frankfurt available, 512 MB RAM / 0.1 vCPU. Not allowed for worker services. Reported to scale to zero when idle.
- **Google Cloud Run:** free usage is limited to US regions; Frankfurt is not covered.

So no free plan gives an always-on API **plus** a separate worker in Frankfurt. Options:

| Option | How it works | Trade-offs |
|---|---|---|
| **A (recommended). One free service: API + in-process worker** on Render Free (Frankfurt) | The worker runs as a background loop inside the API process, reading `paper_processing`. The web app calls the API on upload, which wakes it. | Simple, $0. Cold start of about a minute after idle. A long job can be cut off if the service spins down; the queue's visibility timeout and job records retry it. CPU is small, so a 100-page PDF takes longer. |
| B. Same shape on Koyeb Free (Frankfurt) | As A. | Similar; less CPU (0.1 vCPU). A card may be requested at signup. |
| C. API on Vercel (Python functions, `fra1`) + worker on Render Free | Splits the two. | Two platforms to run; the worker still needs a web wrapper to exist on a free plan; Vercel function time limits. |

The code keeps the API and worker as separate packages either way, so moving to separate paid services later is a deployment change, not a rewrite.

🟢 **Owner chose A (2026-10-22).** No service is created yet; it's created when there's something to run beyond `/health` (M2).

## API sign-in check (JWT verification)
🔵 The hosted project signs sign-in tokens with **ES256** (elliptic-curve key), published at its public JWKS URL.

What the API now does (`apps/api/src/exploraai_api/auth.py`):
- Accepts only ES256/RS256 tokens signed by a key from the project's JWKS. **HS256 and `none` are refused**, so the API needs no JWT secret at all.
- Requires and checks issuer, audience (`authenticated`), expiry, issued-at and subject (10-second clock leeway). Only the `authenticated` role passes; `anon` and `service_role` tokens are refused.
- **Fails closed:** if `SUPABASE_URL` isn't set or the keys can't be fetched, protected routes answer 503, never "allowed".
- Keys are cached for 10 minutes; an unknown key ID triggers a refetch, so key rotation works.
- Tokens are never logged.
- New protected endpoint `GET /me` returns the signed-in user's ID and email (used to test sign-in end to end).

New dependency: `pyjwt[crypto]==2.15.1` (pulls in `cryptography` 50.0.2). Trivy shows no HIGH/CRITICAL findings.

Checks:
- 24 new tests (valid token; missing, malformed, expired, wrong audience/issuer, anon/service/no role, no subject, non-UUID subject, no expiry/issued-at, wrong key, HS256, `none`; unknown key → 401; keys unreachable → 503; not configured → 503; settings validation). 28/28 Python tests pass; Ruff and strict mypy clean.
- Live check against the hosted project's public keys: tokens forged with the real key ID, or with an unknown key ID, are both rejected.

🟠 Known limit: a signed-out user's token stays valid until it expires (Supabase default: 1 hour). Acceptable for the beta; database RLS still applies.
